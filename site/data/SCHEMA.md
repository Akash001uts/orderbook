# Artifact schema, version 1

The site binds to this schema and never to a tool's printed output. That rule is
not stylistic: this repository rewords its stdout deliberately and often, so a
page that scraped it would break on an edit that changed no behaviour. Changing a
field here is a schema version bump.

Every file is emitted by a tool in this repository, opens with the same four keys,
and is written by `json/include/json/writer.hpp`. Two properties of that writer
matter to anyone comparing files: output is pretty printed one value per line, and
every double is written with a fixed decimal count rather than a shortest round
trip form, so the same numbers produce the same bytes on a different standard
library.

## Common header

Present in every artifact except `source.json` and `bench/baseline.json`, which no
tool writes.

| Field | Type | Meaning |
| --- | --- | --- |
| `schema` | integer | This document's version. Currently 1. |
| `tool` | string | `itch_replay`, `ob_strategy_backtest`, or `ob_latency_bench`. |
| `version` | string | Project version, handed to the code by CMake. |
| `provenance.source` | string | Input path exactly as given on the command line. |
| `provenance.source_bytes` | integer | Input size. |
| `provenance.source_sha256` | string or null | Hash of the input, supplied by the caller. Null means unhashed. |
| `provenance.command` | string | The full command line, with `argv[0]` reduced to the program name. |

Paths are repository relative because the CI guard compares bytes and runs in a
different absolute directory than a developer does.

## What is guarded and what is not

This is the most important thing on the page, so it is also stated on the site.

**`data/ci/` is reproducible.** It is generated from `data/qqq_slice.itch`, the one
raw capture this repository commits, by `scripts/generate_ci_artifacts.sh`. A CI
job reruns that script and diffs its output against the committed files, so the
site's numbers provably cannot drift from the code. Same philosophy as the
regression fixtures in `test/`.

**`data/symbols/` is not reproducible, and says so.** Those artifacts come from the
full day 2019-12-30 NASDAQ capture: 8 251 407 909 bytes, gitignored, present on one
machine. A runner cannot fetch it. Each symbol directory therefore carries a
`source.json` naming the capture, its SHA-256, the extraction command, and the
resulting slice's own hash, so the chain from exchange bytes to published number is
recorded rather than asserted. `reproducible_in_ci` is `false` in every one of them.

**`data/bench/latency.json` is a measurement of one machine** and could not be
regenerated by a runner even if the data were there. Its `environment`, `clock`,
`pinning`, and `frequency_scaling` blocks exist so that the figures cannot be read
without their conditions.

## `replay.json`, from `itch_replay --json`

| Field | Meaning |
| --- | --- |
| `symbol` | The symbol replayed. |
| `config.band_levels` | Band width in levels per side. |
| `config.arena_capacity` | Arena slots this run used. |
| `config.max_cold_levels_per_side` | Cold path cap. |
| `config.tick_size` | Tick in scaled price units. 100 is a penny. |
| `config.price_scale` | Scaled units per dollar. 10000 for ITCH. |
| `config.message_limit` | 0 for the whole file. |
| `parse.status` | 0 is a clean parse. |
| `parse.messages` | Messages the parser read, all symbols. |
| `parse.bytes_consumed` | Should equal `provenance.source_bytes`. |
| `parse.unknown_types` | Types the parser did not recognise. |
| `locate.resolved` | Whether the stock directory named this symbol. |
| `locate.code` | The resolved locate code. |
| `messages.applied` | Messages applied to this symbol's book. |
| `messages.other_symbol` | Messages filtered out. |
| `messages.adds` … `messages.system_events` | Counts by type. Trades, cross trades, and broken trades are counted but not applied. |
| `rejections.off_tick_prices` | Prices the configured tick cannot express. A statement about the configuration, not a defect. |
| `rejections.rejected_adds` | Adds the book refused. Any non-zero value makes every downstream number suspect, because liquidity was silently lost. |
| `rejections.unknown_order_references` | Reductions naming an order the book does not hold. A small count is expected at the start of a file, since the session began before the capture did. |
| `book.*` | End of replay state: resting orders, occupied levels per side, band rebases, abandoned rebases, cold levels, cold operations. |
| `sizing.peak_live_orders` | The high water mark. |
| `sizing.peak_live_orders_at_message` | Which message the peak happened on, which is what `--depth-at-peak` anchors the ladder to. |
| `sizing.arena_capacity` | What this run allocated. |
| `sizing.library_arena_default` | The library default, which is what the sizing story is about. `itch_replay` runs a larger arena on purpose because it is pointed at symbols whose depth is unknown before the run. |
| `sizing.peak_occupied_levels` | Both sides summed. |
| `sizing.touch_low_tick`, `touch_high_tick`, `touch_span_ticks` | Range of the touch across the replay, null if the book never had two sides. |
| `sizing.touch_span_band_percent` | That span as a percentage of the band. |
| `final_touch.bid_tick`, `bid_price`, `ask_tick`, `ask_price` | Null when that side is empty. |

## `depth.json`, from `itch_replay --json-depth`

A ladder snapshot, a separate file so that no number has two homes.

**Not the end of replay.** A full trading day closes with the book emptied by the
session close, so an end of replay ladder over a whole day is correct and shows
nothing. Every ladder here is taken with `--depth-at-peak`, at the message where
the live order count reached its high water mark. That anchors it to the deepest
moment of the session rather than to an arbitrary offset, and it is the same moment
the sizing block reports.

| Field | Meaning |
| --- | --- |
| `levels_per_side` | How many levels were requested. Arrays may be shorter. |
| `captured_at_message` | Which message the snapshot was taken after. |
| `captured_at_peak_depth` | Whether that message was the live order count peak. |
| `live_orders_at_capture` | Live orders at that moment. |
| `bid_tick`, `bid_price`, `ask_tick`, `ask_price` | The touch at that moment. Null when that side was empty. |
| `occupied_bid_levels`, `occupied_ask_levels` | Totals across the whole book at that moment, not just the levels listed. |
| `bids`, `asks` | Arrays ordered from the touch outward: bids descending, asks ascending. |
| `bids[].tick`, `.price` | Tick index and scaled price. |
| `bids[].quantity` | Aggregate resting quantity at that level. |
| `bids[].orders` | Order count at that level. |

## `backtest.json`, from `ob_strategy_backtest --json`

| Field | Meaning |
| --- | --- |
| `config.*` | Symbol, quote offset in ticks, quote size, position limit, inventory skew, reaction latency in microseconds. Zero latency is an idealised bound, not a realistic setting. |
| `replay.messages_seen`, `messages_applied` | Feed coverage. |
| `pnl.spread`, `inventory`, `fees`, `total` | Attribution in ticks times shares, which `pnl.unit` states. |
| `risk.final_position`, `max_long`, `max_short`, `time_holding_ns`, `max_drawdown` | Read the markouts against `time_holding_ns`, not on their own. |
| `activity.fills`, `filled_shares`, `quoted_shares`, `fill_ratio` | |
| `activity.trade_through_fills` | Fills inferred from the market trading past our price. |
| `activity.quotes_placed`, `quotes_cancelled`, `quotes_rejected` | Rejections are post-only. |
| `activity.cancels_too_late` | Cancels that arrived after their target had already filled. Zero without a reaction latency, by construction. |
| `activity.limit_overshoot_shares` | Shares beyond the position limit, from quotes in flight when it was reached. |
| `sharpe.value` | Descriptive only. Null if the sample was degenerate. |
| `sharpe.samples`, `informative_samples` | One second samples, and how many were non-zero. |
| `sharpe.clears_minimum_events` | False means fewer than 30 fills, so a mean and a standard deviation do not describe anything. |
| `sharpe.annualised` | Always false. |
| `markouts[]` | One entry per horizon: `horizon` label, `horizon_ns`, and signed P&L per share for `buy_per_share`, `sell_per_share`, `all_per_share`, with the `fills` behind them. Persistently negative markouts mean the fills are adversely selected. |
| `unresolved_markouts` | Fills whose longest horizon had not elapsed when the replay ended. A horizon that is mostly unresolved has not been measured. |
| `crossed_book.*` | Intervals, nanoseconds, observation counts, `locked_observations` counted separately from crossed, worst depth in ticks, and the crossed percentage of book updates. A crossed interval is time the quote sat inside the real spread with nobody trading against it. |

## `sweeps.json`, from `ob_strategy_backtest --sweep --latency-sweep --json`

Both grids in one document. Either array is absent if its flag was not given.

`parameter_sweep[]` carries `offset_ticks`, `skew_ticks`, `size`, then
`total_pnl`, `spread`, `inventory`, `fees`, `fills`, `fill_ratio`,
`max_drawdown`, `markout_1s_per_share`, `crossed_percent`.

`latency_sweep[]` carries `latency_us`, then `total_pnl`, `spread`, `inventory`,
`fills`, `filled_shares`, `fill_ratio`, `quotes_placed`,
`markout_1s_per_share`, `crossed_percent`.

Two readings that the site must not get wrong, both recorded at length in
STRATEGY.md and printed with the CSV:

The parameter grid is sensitivity analysis, not a search for an edge. It covers one
symbol on one day, so the best cell is a property of that day.

In the latency grid, fills rise as latency grows and that is not latency helping.
The cancel is delayed as well as the placement, so a quote the strategy has already
decided to pull stays resting and fillable for the whole window. The 1 s markout is
what those extra fills are worth, and it falls. Total P&L is not monotonic in
latency and should not be drawn as if it were.

## `latency.json`, from `ob_latency_bench --json`

| Field | Meaning |
| --- | --- |
| `environment.*` | CPU brand, hardware threads, OS, compiler, build type, exact compile flags. The flags come from the build rather than from a literal, so they cannot drift. |
| `clock.source` | `invariant_tsc` or `steady_clock`. |
| `clock.ticks_per_ns` | Calibrated against `steady_clock` at startup. |
| `clock.cpuid_available`, `tsc_invariant` | Verified through CPUID leaf `0x80000007`. |
| `clock.fallback_reason` | Empty when the TSC is in use. |
| `clock.overhead_ns` | The timer's own cost, median of 4096 back to back reads. |
| `clock.overhead_subtracted` | Always false. Subtracting a noisy estimate from every sample would corrupt the tail, which is the part that matters. |
| `pinning.status` | `pinned`, `not_requested`, `unsupported`, or `failed`. Pinning is not isolation. |
| `frequency_scaling.status` | `active`, `disabled`, or `unknown`. Unknown on Windows, which is honest rather than a pass. |
| `degraded_conditions` | Count of the above that were not ideal. Non-zero is a caveat the site must show. |
| `input.*` | Symbol, arena slots, warmup runs, measured runs, messages per run. |
| `latency_ns[]` | Per message type plus an `ALL` row: `bucket`, `count`, `p50`, `p90`, `p99`, `p99_9`, `p99_99`, `max`, `mean`. Nanoseconds, from HdrHistogram at three significant figures across a 1 ns to 1 s range. |
| `max_is_a_scheduling_event` | Always true. On a core the OS can interrupt, a millisecond scale max is a scheduling event, not a rebase. p99.9 and p99.99 are the tail figures worth reading. |
| `throughput.mean_messages_per_second` | From separate uninstrumented runs. |
| `throughput.measured_uninstrumented` | Always true. Latency and throughput cannot be measured in the same pass: two timestamp reads and two fences cost about as much as a message does. |
| `throughput.run_to_run_cv_percent`, `runs[]` | Variance, reported rather than averaged away. |

## `baseline.json`, the comparative baseline

Hand written rather than tool emitted, so it does not carry the common header's
`provenance` block. It is the single source for the `std::map` comparison the hero
panel shows and for the baseline and allocation tables in BENCHMARKS.md, which
`scripts/sync_benchmarks.py` renders from it. Updating it after an accepted
benchmark run, then running that script, is the whole update path; the site derives
every display string and ratio from the numeric fields here.

| Field | Meaning |
| --- | --- |
| `schema` | This document's version. Currently 1. |
| `tool` | `ob_baseline_bench`, the program the figures came from. |
| `version` | Project version, matching the other artifacts. |
| `benchmark_command` | The exact command line that produces these numbers. |
| `repetitions` | Benchmark repetitions behind each figure. |
| `statistic` | The statistic reported, `median`. |
| `rows[]` | One per operation: `id` a stable identifier, `label` a display string, `flat_ns` and `naive_ns` the two timings in nanoseconds, and `interpretation`. |
| `rows[].interpretation` | `faster` when the flat book wins and the ratio is worth stating, or `below_resolution` when the figure is below what the harness can resolve and a ratio would mislead. The site chooses its wording from this rather than from the numbers. |
| `query_noise_floor_ns` | The empty loop floor the best price query is measured against. |
| `allocations_per_add.flat`, `.naive` | Allocations per add, counted exactly by the `operator new` replacement. Zero for the flat book. |

## `source.json`, per symbol directory

Written by `scripts/generate_symbol_artifacts.sh`, not by a tool, because no tool
sees both ends of the chain it records.

| Field | Meaning |
| --- | --- |
| `capture`, `capture_bytes`, `capture_sha256` | The full day capture the slice came from. |
| `extract_command` | The `itch_replay --extract` invocation that produced the slice. |
| `slice`, `slice_bytes`, `slice_sha256` | The slice every artifact in this directory names in its provenance block. |
| `reproducible_in_ci` | Always false here. |
| `note` | Why. |

## `index.json`

Built by `scripts/build_index.py` from the committed per symbol artifacts, so it is
a pure function of files already in the repository and CI can rebuild it and diff
it. It exists so the selector can render a button and a one line summary per symbol
before any detail file loads.

| Field | Meaning |
| --- | --- |
| `schema` | 1. |
| `generated_by` | `scripts/build_index.py`. |
| `default_symbol` | Which symbol the site preselects. |
| `symbols[]` | One entry per symbol, in the order the selector shows them. |
| `symbols[].symbol` | Ticker, and the directory name under `symbols/`. |
| `symbols[].messages_applied` | Messages applied to that symbol's book. |
| `symbols[].peak_live_orders` | High water mark of live orders. |
| `symbols[].library_arena_default` | For the headroom comparison. |
| `symbols[].bid_price`, `ask_price` | The touch from `depth.json`, so at the deepest moment rather than at the close. A full day's final touch is null for every symbol, which is correct and useless in a summary line. |
| `symbols[].price_scale` | Scaled units per dollar, so a reader does not have to assume. |
| `symbols[].touch_span_ticks` | How far the touch travelled across the replay. |
| `symbols[].baseline_total_pnl` | From `backtest.json`. |
| `symbols[].fills` | From `backtest.json`. |
| `symbols[].off_tick_prices`, `rejected_adds`, `rebases`, `cold_levels` | The cross symbol variation the site is there to show. A non-zero `rejected_adds` would invalidate every other number for that symbol. |
| `symbols[].reproducible_in_ci` | From `source.json`. |
